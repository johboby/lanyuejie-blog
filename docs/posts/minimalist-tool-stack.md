# 极简工具主义：我只用这8个App管理整个生活和工作

## <span id="先说结论工具越少系统越强">先说结论：工具越少，系统越强</span>

> 2023年我的手机有63个App、电脑有89个程序。2026年的今天，**我只有8个App管理全部生活和工作**——写作、任务、日历、笔记、财务、健康、密码、通讯，一个不少。

| 维度 | 2023年（63个App）| 2026年（8个App）| 变化 |
|---|---|---|---|
| App总数 | 63 | **8** | **-87%** |
| 日均打开App数 | 18 | **5.2** | **-71%** |
| 决策"该用哪个"的次数/天 | ~25次 | **~3次** | **-88%** |
| 任务完成率（周）| 52% | **89%** | **+37pp** |
| 每周"工具维护"时间 | 3.5h | **0.5h** | **-86%** |
| 跨设备同步故障次数/月 | 8-12次 | **0-1次** | **-92%** |
| 年度工具订阅费 | $1,240 | **$312** | **-75%** |
| 心情"被工具烦到"频率 | 每天 | **几乎不** | 质变 |

**三个核心认知**（后面逐一展开论证）：

> **① 工具之间的"缝隙"才是真正的时间黑洞。** 不是单个工具慢，而是"在5个工具之间跳转+格式转换+重复输入"吃掉了你30%的精力。

> **② 每个工具只做一件事，且做到极致。** 我的8个App没有一个是"瑞士军刀"，全部是"专用手术刀"。

> **③ 工具系统的价值不在数量，在"数据流"。** 8个工具之间有清晰的信息流向——任务从哪来、笔记去哪存、日历怎么同步——设计好这条管道，比多装10个App有用100倍。

### 关键转折点

| 日期 | 事件 | 触发思考 |
|---|---|---|
| 2023.08 | 发现一周内打开了47个不同的App | "我在工作还是在管理工具？" |
| 2024.03 | 记不清某个笔记存在哪个App里 | "搜索功能再强，找不到=不存在" |

> **核心顿悟**（2024年11月）：我删掉的30个App里，没有一个让我"回不去了"。每次删除后等一周，发现生活照常运转——那个App只是在"假装有用"。

## <span id="深度拆解每个工具为什么留下">深度拆解：每个工具为什么留下</span>

### ① Obsidian —— 写作+知识库（核心中的核心）

| 项目 | 说明 |
|---|---|
| **用途** | 所有写作（文章/博客/脚本）、读书笔记、闪念记录、知识图谱 |
| **为什么留下** | 本地存储（数据100%属于我）、Markdown（永不过时）、双向链接（知识自然生长）、插件生态（可扩展但不强迫）|
| **替代了什么** | Notion（笔记部分）、Bear、Typora、Roam Research、Logseq、Evernote、Apple Notes |
| **每天打开次数** | 15-25次 |
| **核心工作流** | Quick Capture（闪念）→ Daily Note（当天整理）→ MOC（中间层索引）→ 正式文章/笔记 |
| **关键插件** | Templates、Quick Switcher++、Dataview、Canvas |

> **一句话**：Obsidian是我的"第二大脑"，所有想法最终归宿都在这里。它不联网、不上传、不订阅——是数字世界里的"纸质笔记本+活页夹"的完美数字化。

### ② Things 3 —— 任务管理（执行引擎）

| 项目 | 说明 |
|---|---|
| **用途** | 个人任务、项目分解、今日待办、 someday/maybe清单 |
| **为什么留下** | 设计极致、键盘流操作、与日历并排显示、Magic Plus（快速录入）、天然支持GTD |
| **替代了什么** | Todoist、TickTick、Apple Reminders、Microsoft To Do、Linear（个人部分）|
| **每天打开次数** | 8-12次 |
| **核心工作流** | Inbox（收集）→ Today（今日）→ Upcoming（展望）→ Projects（项目）→ Someday（暂缓）|
| **不用的功能** | 标签（用项目替代）、重复任务（用日历替代）|

> **一句话**：Things是"把想法变成行动"的转换器。在Obsidian里产生想法，在Things里变成可执行步骤。两者配合=思考+执行。

### ③ Fantastical —— 日历（时间的地图）

| 项目 | 说明 |
|---|---|
| **用途** | 所有日程、会议、时间块规划、提醒 |
| **为什么留下** | 自然语言输入（"明天下午3点和医生"→自动创建）、与Things并排视图、Apple生态深度集成 |
| **替代了什么** | Apple Calendar、Google Calendar（独立使用）、Calendly（用Fantastical+手动替代）|
| **每天打开次数** | 5-8次 |
| **核心工作流** | 时间块预规划（每周日）→ 每日晨间检查 → 事件后5分钟复盘 |

> **一句话**：日历不是"记录去了哪里"，是"决定要成为什么"。每个周日我用Fantastical做下周时间块规划，确保深度工作、运动、家庭时间都有固定位置。

### ④ 1Password —— 密码管理（安全基石）

| 项目 | 说明 |
|---|---|
| **用途** | 所有密码、2FA密钥、信用卡、软件License、身份文件 |
| **为什么留下** | 端到端加密、跨设备同步、Watchtower（泄露监控）、SSH密钥管理、钓鱼保护 |
| **替代了什么** | 浏览器自带密码管理器、Authy、Google Authenticator |
| **每天打开次数** | 自动填充为主，主动打开2-3次 |
| **核心价值** | 一个主密码守护一切，告别"密码复用"这个最大安全漏洞 |

> **一句话**：1Password是整套系统的"信任根基"。如果它崩了，一切数字身份都危险。所以它在"安全"这件事上做到极致，其他事一概不做——这正是我选它的原因。

### ⑤ Notion —— 团队协作/轻量数据库（唯一保留的"多功能"工具）

| 项目 | 说明 |
|---|---|
| **用途** | 团队共享文档、项目看板、轻量数据库（订阅者管理）、公共知识库 |
| **为什么留下** | 团队已经在用、数据库视图灵活、免费版够用、API可对接 |
| **替代了什么** | Airtable（部分）、Trello（团队看板）、Google Docs（协作部分）|
| **每天打开次数** | 3-5次 |
| **使用边界** | **只用于"需要和他人共享"的内容**。个人笔记/写作全在Obsidian |

> **一句话**：Notion是唯一"多功能"的例外，因为它解决的是"多人协作"这个Obsidian不擅长的场景。但严格限制用途——它不存我的个人笔记。

### ⑥ Ledger —— 财务管理（开源极简）

| 项目 | 说明 |
|---|---|
| **用途** | 日常记账、投资追踪、预算控制、年度财务复盘 |
| **为什么留下** | 纯文本账本（和Obsidian一样的哲学）、版本可控、脚本可分析、不依赖任何服务商 |
| **替代了什么** | YNAB、MoneyTracker、随手记、Excel表格 |
| **每天打开次数** | 1-2次（记账+查看）|
| **核心工作流** | 每天睡前3分钟记当日支出 → 每周汇总分类 → 每月分析趋势 |

> **一句话**：Ledger是"纯文本会计系统"，账本是一个`.ledger`文件，可以用任何编辑器打开。10年后这个文件依然可读——不像任何App的导出格式。

### ⑦ AutoSleep —— 健康追踪（睡眠+运动）

| 项目 | 说明 |
|---|---|
| **用途** | 睡眠阶段分析、心率趋势、运动闭环、睡前提醒 |
| **为什么留下** | 与Apple Watch深度集成、自动追踪（零操作）、数据可视化清晰 |
| **替代了什么** | Oura App（只保留配套Ring）、Sleep Cycle、Apple原生健身 |
| **每天打开次数** | 1-2次（晨起看睡眠+傍晚看运动）|
| **核心价值** | 早起实验的数据来源（见前文），健康是一切效率的地基 |

> **一句话**：工具再好，身体垮了全白搭。AutoSleep让我对睡眠质量有精确的反馈，从而优化作息——它和早起实验是同一套系统的不同侧面。

### ⑧ Signal —— 通讯（隐私优先）

| 项目 | 说明 |
|---|---|
| **用途** | 私人加密通讯、重要群组、敏感工作沟通 |
| **为什么留下** | 端到端加密、开源协议、无广告无追踪、跨平台 |
| **替代了什么** | WhatsApp（隐私担忧）、Telegram（部分）、iMessage（跨平台需求）|
| **每天打开次数** | 5-10次 |
| **使用原则** | 工作通讯走团队工具（飞书/Slack），私人通讯走Signal，严格分离 |

> **一句话**：通讯工具是"数字生活的空气"——你不会每天想着它，但没有它寸步难行。Signal做一件事：安全地把消息从A传到B，不做其他任何事。

## <span id="数据流设计8个工具如何协同">数据流设计：8个工具如何协同</span>

### 核心数据流（信息如何流动）

```
┌─────────────────────────────────────────────────────┐
│                  信息输入端                          │
│  Signal（消息）  Fantastical（日程）  外部世界      │
└────────┬───────────────┬───────────────┬───────────┘
         │               │               │
         ▼               ▼               ▼
    ┌─────────┐    ┌─────────┐    ┌──────────┐
    │ Things  │    │Things   │    │ Obsidian │
    │ (任务)  │    │(时间块) │    │ (笔记)   │
    └────┬────┘    └────┬────┘    └────┬─────┘
         │              │              │
         └──────────────┼──────────────┘
                        ▼
                ┌───────────────┐
                │  Obsidian     │ ← 所有思考/写作的终点
                │  (知识库)     │
                └───────┬───────┘
                        │
           ┌────────────┼────────────┐
           ▼            ▼            ▼
      ┌────────┐  ┌────────┐  ┌────────┐
      │ Notion │  │ 发布/  │  │ Ledger │
      │(共享)  │  │ 交付   │  │(记账)  │
      └────────┘  └────────┘  └────────┘
```

### 三个关键数据流规则

| 规则 | 说明 | 示例 |
|---|---|---|
| **规则1：单向流动** | 信息从"输入端"流向"处理端"，不回头 | Signal消息→Things生成任务→执行→完成，不反向 |
| **规则2：一处录入** | 每个信息只在一个地方首次记录 | 想法进Obsidian，不同时在Things和Notion记 |
| **规则3：自动同步** | 工具间通过导出/API/共享文件传递 | Obsidian文章→复制发布；Things完成→Notion更新状态 |

### 典型场景的完整流程

#### 场景A：收到一个新项目

```
1. Signal收到客户消息 → 复制关键信息
2. 粘贴到 Obsidian Daily Note（Quick Capture）
3. 在 Things 创建项目 → 分解为3-5个任务
4. Fantastical 分配时间块（深度工作2h×3天）
5. 执行过程中所有笔记/草稿在 Obsidian
6. 交付物通过 Notion 共享给客户
7. 收入记录到 Ledger
```

#### 场景B：一个想法变成一篇文章

```
1. 散步时闪念 → 手机 Obsidian（Quick Add）
2. 晚上整理到 Daily Note → 归类为"待展开"
3. 周末在 Obsidian 中展开为大纲 → 填充内容
4. 完成后 → 复制到博客发布系统
5. 文章链接存回 Obsidian 对应笔记（双向链接）
```

### "删除测试"方法论

每个候选删除的工具，我做一次**7天实验**：

```
Day 1-2：删除App，观察焦虑感
Day 3-5：记录"因为没有它"造成的实际损失
Day 6-7：决定是否恢复
结果统计：
  → 恢复了：8个（最终留在系统里）
  → 没恢复：45个（彻底删除）
  → 恢复后又删：5个（反复横跳后确认不需要）
```

> **核心发现**：45个没恢复的工具里，有41个在删除后的7天里**完全没有造成实际损失**。它们之前的存在只是"心理上的安全感"——让你觉得"我有工具可以用"，而不是"我真的在用"。

## <span id="极简工具主义的5条原则">极简工具主义的5条原则</span>

### 原则一：一个工具一个核心用途

| ❌ 违反 | ✅ 遵守 |
|---|---|
| Notion既做笔记又做任务又做数据库又做网站 | Obsidian=笔记、Things=任务、Notion=只做协作 |
| 用微信既聊天又工作又支付又看公众号 | Signal=私人通讯、飞书=工作、支付宝=支付 |
| 用同一个App记"今天的想法"和"三年计划" | 闪念进Inbox、长期知识进MOC，分层存储 |

> **判断标准**：如果你不能用一句话说清"这个App是干什么的"，它大概率在干太多事——或者你在错误地使用它。

### 原则二：数据流优先于功能

选择工具时，问的不是"它能不能做XX"，而是"它产出的东西怎么流向下一个工具"。

| 决策场景 | 错误问题 | 正确问题 |
|---|---|---|
| 选笔记工具 | "它支持多少种格式？" | "笔记写完后怎么变成文章/任务？" |
| 选任务工具 | "它有没有子任务/标签/过滤器？"| "任务完成后怎么归档/复盘？" |
| 选通讯工具 | "它有没有表情包/视频通话？"| "对话中的重要信息怎么提取到笔记？" |

### 原则三：本地优先 > 云端优先

| 本地优先（我的选择）| 纯云端 |
|---|---|
| Obsidian（本地Markdown）| Google Docs |
| Ledger（本地文本文件）| 在线记账网站 |
| 1Password（本地加密库）| 浏览器密码管理 |
| Things（本地+iCloud同步）| 纯Web任务工具 |

> **为什么**：10年后，你的Markdown文件依然可读，但很多2023年的Web App已经关站了。本地优先=数据永生。

### 原则四：订阅焦虑 < 一次性付费 < 免费开源

| 付费模式 | 心理负担 | 典型代表 | 我的态度 |
|---|---|---|---|
| 月付订阅 | 高（每月提醒"还在扣钱"）| Notion Plus、Todoist Pro | 尽量避免 |
| 年付订阅 | 中（一年想一次）| Fantastical、1Password | 可接受 |
| 一次性付费 | 低（买断即忘）| Things 3（$49买断）| **最优选** |
| 免费开源 | 零 | Obsidian、Ledger | **最佳** |

> 我的8个工具里：**3个免费开源**（Obsidian/Ledger/Signal）、**2个一次性付费**（Things）、**2个年付订阅**（Fantastical/1Password）、**1个免费增值**（Notion免费版）。年度总支出$312。

### 原则五：工具适应你，不是你适应工具

| ❌ 你适应工具 | ✅ 工具适应你 |
|---|---|
| 为了用Notion的数据库功能，把笔记硬塞进去 | Obsidian的文件夹结构按我的思维方式组织 |
| 为了用番茄钟App，把工作切成25分钟块 | Things的计时功能适配我自然的工作节奏 |
| 为了用某个All-in-One，改变整个工作流 | 每个工具围绕我已有的习惯设计 |

## <span id="ai层的正确用法">AI层的正确用法</span>

### AI不是第9个App，是"水电煤"

| 维度 | 传统App | AI助手（ChatGPT/Claude）|
|---|---|---|
| 定位 | 有固定用途的"工具" | 嵌入所有工具的"能力层" |
| 打开方式 | 点击图标 | 在任何工具中调用 |
| 使用场景 | 特定任务 | 所有任务的加速器 |
| 类比 | 螺丝刀/锤子 | 电动马达（装在每把工具上）|

### AI在我的8工具系统中的嵌入点

| 工具 | AI怎么用 | 效果 |
|---|---|---|
| **Obsidian** | AI帮我润色/结构化/查资料 | 写作速度3x |
| **Things** | AI帮我分解项目为任务 | 规划时间减半 |
| **Fantastical** | AI推荐最佳时间块安排 | 日程冲突减少 |
| **1Password** | AI生成超强密码 | 安全性提升 |
| **Notion** | AI总结协作文档/生成报告 | 团队效率提升 |
| **Ledger** | AI分析消费趋势/给建议 | 理财决策更优 |
| **AutoSleep** | AI解读睡眠趋势/给建议 | 睡眠质量改善 |
| **Signal** | （不用AI，保持纯通讯）| — |

> **关键原则**：AI是"增强层"不是"替代层"。它让每个工具更好用，但不替代工具本身。就像电动马达让螺丝刀更强，但你还是需要螺丝刀。

## <span id="faq">FAQ</span>

### 1. 为什么不用All-in-One工具（如Notion万能论）？

All-in-One的代价是"每个功能都做到80分"。我的策略是"每个功能选95分的专项工具"，用清晰的数据流连接它们。Notion我用了2年，最终发现：笔记体验不如纯文本编辑器、任务管理不如专项To-Do、数据库不如真正的BI工具。它适合"轻量一切"的用户，不适合"每个场景都要深度"的用户。最终我把Notion降级为"纯知识库"，只保留一个用途。

### 2. 8个App不会太少了？有些场景覆盖不到吧？

少不是目的，"无重叠+全覆盖"才是。我的8个App覆盖了：写作、任务管理、日历、笔记/知识库、财务、健康、密码、通讯——生活和工作全部场景。判断标准不是"数量少"，而是"打开任何一个App都能立刻知道该干什么"。如果某个场景需要第9个工具，我不会硬撑，而是先问"能不能合并到现有8个里"。3年里加过又删掉的工具超过47个，每次删除都是一次认知升级。

### 3. 如何处理"工具切换"的认知开销？

关键设计：每个工具只有一个核心用途，且用途之间边界清晰。Obsidian=写、Things=管任务、Fantastical=看时间、1Password=填密码——大脑不需要"思考该用哪个"，场景自动映射到工具。我做过一个实验：记录一周内"犹豫该用哪个工具"的次数，从最初的每天5-6次降到现在的每周0-1次。这叫"认知自动化"——通过严格单用途+固定位置，让工具选择变成肌肉记忆。

### 4. 团队协作怎么办？个人工具和团队工具冲突时选哪个？

原则：个人系统优先，团队工具做"接口"而非"中心"。我在团队工具（Slack/飞书/Linear）里只做"接收和回复"，所有思考、规划、写作都在个人系统完成，然后"导出"到团队工具。这样即使换工作/换团队，我的个人系统不变。具体做法：团队消息→Things生成任务→Obsidian深度处理→回团队工具交付。个人系统是"大脑外挂"，团队工具是"对接口"，两者不混淆。

### 5. AI工具不算在这8个里吗？

算，但有特殊性。我把AI助手（ChatGPT/Claude）视为"通用协处理器"而非"App"——它不像其他工具那样有固定用途，而是嵌入到每个工具的使用流程中。写文章时调用、做数据分析时调用、查资料时调用。所以它不占"8个"的名额，更像是"水电煤"——底层基础设施。如果非要把它算进来，那我的系统是"8+1"——8个App+1个AI层。

### 6. 多久做一次工具审计？怎么判断该删掉什么？

我每季度做一次"工具审计"，标准很简单：①过去90天打开次数<10次→候选删除；②和现有工具功能重叠>50%→合并；③没有它也能正常运转>2周→可删。删除后观察2周，如果没回来找它，就彻底卸载。最近一次审计（2026 Q2）删掉了3个：一个PDF工具（合并到系统预览）、一个番茄钟App（合并到Things的计时功能）、一个稍后读工具（合并到Obsidian的Inbox）。工具越少，每个工具的使用深度越深，熟练度复利越高。

## <span id="写在最后">写在最后</span>

### 三个值得记住的数字

> **8** — 管理全部生活和工作的App数量。不是"极简到痛苦"，而是"精准到每个都有不可替代的理由"。

> **47** — 被我删除的工具数量。每次删除都是一次认知升级：原来这个工具一直在"假装有用"。

> **$312** — 年度工具总支出。从$1,240降到$312，省下的不只是钱，更是注意力和决策能量。

### 最后一句话

> **工具是手指的延伸，不是大脑的替代品。** 当你有63个App时，你在管理工具；当你只有8个时，你在管理生活。

> **极简工具主义的终点不是"少"，是"清晰"——清晰地知道每个工具做什么、信息从哪里来、到哪里去、为什么需要它。**

> **2026年，工具比任何时候都多、都便宜、都"智能"。但"拥有更多工具"和"拥有更好的系统"之间，隔着一道叫做"克制"的窄门。**

> **推开它，你会发现：8个工具，够了。**
