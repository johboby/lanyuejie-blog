我先说结论。

Cursor 正式发布了 **Agent SDK**——允许开发者以"代码文件夹"的形式定义智能体，用评估（evals）测试它，然后一条命令部署到 Cursor 或自己的基础设施。

**这个 SDK 最核心的一句话，写在 Cursor 官方博客的标题里——"An agent is a project"（一个智能体就是一个项目）**。

这句话在过去两年 AI 编程工具行业里，是被反复提及但从未被真正产品化的概念。Cursor 的 Agent SDK 是第一个把这句话变成可执行工具的产品。

## 一个智能体就是一个项目

Cursor 官方的 Agent SDK 文档里，定义智能体的方式非常简单——

- **一个智能体是一个文件夹**
- `instructions.md` 是这个智能体的提示词（prompt）
- `tools/` 目录里的每个文件，是一个类型化的动作，模型可以调用它
- `skills/` 目录里存放的是模型按需加载的流程

**这个定义方式看起来朴素，但它改变了一个根本性的东西——智能体的"定义"从"一段提示词"变成了"一个可版本管理的软件项目"**。

在过去两年，大多数 AI 编程工具的智能体定义方式，是一个 JSON 配置文件或一串系统提示词。**它们不可测试、不可部署、不可复用**。

Cursor 的 Agent SDK 把这个定义方式推翻了——**智能体现在是一个可以 `git init`、可以 `npm test`、可以 `deploy` 的普通软件项目**。

## 三条命令

Cursor 官方给的三条命令，把智能体生命周期完全展开——

```
npx @cursor/agent-sdk init ./my-bot
agent-sdk dev
agent-sdk deploy
```

**第一条命令**：初始化一个智能体项目，生成一个包含 `instructions.md`、`tools/`、`skills/` 的文件夹。

**第二条命令**：本地启动智能体，并通过 playground 交互式测试。

**第三条命令**：一条命令部署到 Cursor 基础设施。

**这三条命令加在一起，意味着——智能体的开发流程，从"写提示词、试错、上线"变成"写代码、测试、部署"**。

这是过去两年 AI 编程工具行业最重要的一次产品化转型。

## 关于"部署到 Cursor 或自己的基础设施"

Agent SDK 文档里有一个细节值得单独看——**"部署到 Cursor 或你自己的基础设施"**。

这个"或"字，是 Agent SDK 最重要的产品判断。

**如果只能部署到 Cursor，那 Agent SDK 只是 Cursor 的一个功能。但能部署到自己的基础设施，它就是一个平台。**

Cursor 选择把 Agent SDK 做成"可以部署到任何地方"的开放框架，这背后是一个商业判断——**Cursor 的野心，不是做"一个更好的编辑器"，而是做"AI 智能体的开发平台"**。

这个定位变化，意味着 Cursor 从"IDE 工具"升级成了"智能体基础设施"。**它的竞争对手，从 VS Code、Windsurf，变成了——所有做 agentic coding 平台的公司**。

## Cursor 用它构建了自己的三个智能体

Cursor 官方博客明确说，Agent SDK 就是 Cursor 自己用来构建托管智能体的框架——**Bugbot、Security Reviewer、Rollouts**。

这三个智能体，是 Cursor 产品里已经上线的真实智能体——

- **Bugbot**：自动检测代码库中的 bug
- **Security Reviewer**：自动审查代码安全
- **Rollouts**：管理代码部署流程

**这三个智能体是 Agent SDK 的"吃自己的狗粮"（dogfooding）案例**。Cursor 用 Agent SDK 构建自己的生产级智能体，等于向开发者证明——**这套框架已经经过了 Cursor 自己的生产验证**。

## 为什么"Agent as code"是一个真正的变化

"Agent as code"（智能体即代码）这个概念，比表面看起来要深刻得多。

在过去两年，AI 编程工具的智能体几乎都是"提示词驱动的黑盒"——

- 你写一段系统提示词
- 模型在后台执行
- 你通过聊天窗口看到结果

**这种模式的问题在于——你无法知道智能体内部做了什么，无法测试它，无法复用它，无法把它交给另一个团队**。

Cursor 的 Agent SDK 把这套黑盒变成了白盒——

- `instructions.md` 定义智能体的行为边界
- `tools/` 定义它可以调用的动作
- `skills/` 定义它可以加载的流程
- `evals` 定义它如何被测试

**这套"白盒"模式，意味着智能体可以被代码审查、被版本控制、被 CI/CD 测试、被团队协作**。

**这是过去两年 AI 编程工具行业最重要的成熟度标志——智能体从"黑盒提示词"变成"可测试的软件"**。

## 一个更深的观察

写到这里，我想说一句可能不太好听但确实存在的话。

**Cursor 的 Agent SDK，本质上是把"智能体"从"产品"降格成了"项目"**。

这个"降格"是一个褒义词——它意味着智能体不再是"某个公司的专属功能"，而是"任何开发者都可以自己构建、自己部署、自己拥有的东西"。

**这个转变对行业的意义是——AI 智能体的"定义权"，从 Cursor 这样的平台公司，转移到了开发者手中**。

在过去，开发者只能选择"用 Cursor 内置的智能体"或"自己写提示词"。

现在，开发者可以——

- 用 Agent SDK 定义自己的智能体
- 用 `evals` 测试它
- 用 `agent-sdk deploy` 部署到自己的基础设施
- 把它当成一个普通软件项目来管理

**这是 AI 编程工具行业第一次把"智能体定义权"开放给开发者**。

## 关于 2026 年 6 月 Cursor 移动端的背景

Agent SDK 发布的同一年，Cursor 还做了一件事——2026 年 6 月 30 日，Cursor 推出 iOS 移动端应用，进入公开测试，面向所有付费计划用户开放。

**Cursor 移动端的核心功能，是把 PC 上的智能体"远程化"**——

- 用户打开 Cursor 移动端后，可以选择代码仓库、模型
- 通过语音输入或斜杠命令启动智能体
- 远程控制正在个人电脑上运行的智能体
- 在手机端跟进任务进度、查看代码差异、直接合并

**Cursor 移动端 + Agent SDK，是 Cursor 2026 年的两个最重要的产品决策**——

- **移动端**：把智能体的"使用"从桌面延伸到移动
- **Agent SDK**：把智能体的"定义"从平台开放给开发者

**这两个决策放在一起，Cursor 完成了从"AI 编程工具"到"AI 智能体平台"的转型**。

## 写在最后

Cursor 的 Agent SDK 在 2026 年 11 月的发布，是 AI 编程工具行业过去两年最重要的一次产品化转型。

**它的核心价值不是"又一个 SDK"，而是——它第一次把"智能体"从"产品"变成了"项目"**。

一个智能体就是一个项目——这句话的深意是——**智能体的未来，不是"更聪明的模型"，而是"更好管理的软件"**。

**当智能体可以像软件一样被版本管理、被测试、被部署、被协作，它才真正具备了"规模化生产"的能力**。

**这个判断，比 Agent SDK 本身的任何技术细节都重要**。
